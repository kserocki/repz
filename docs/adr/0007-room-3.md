# ADR-0007: Room 3

- **Status:** Accepted (2026-10-28)

## Context
Krzysztof wants the newest Kotlin-first stack. Room 3.0.x is stable.

## Decision
Use `androidx.room3` 3.0.3 with KSP per target and the bundled SQLite driver.

## Consequences
Fewer examples online, so verify APIs against official docs. KSP wiring with the AGP 9 KMP library plugin is verified in the first spike (REP-6): Room 3.0.3 + KSP 2.3.12 generate `actual` code for `kspAndroid`, `kspIosArm64` and `kspIosSimulatorArm64` under `com.android.kotlin.multiplatform.library` (AGP 9.4.0), and the probe DAO suite (suspend query, `Flow`, `withWriteTransaction` rollback) passes on the Android host test JVM and the iOS 27.1 simulator. `androidx.sqlite:sqlite-bundled` ships Android-only natives, so `BundledSQLiteDriver` cannot load on the host test JVM: `androidHostTestRuntimeClasspath` substitutes `sqlite-bundled-jvm` at the same catalog version, scoped to that one configuration; the Android app's own runtime classpath keeps the Android variant.
- Android host tests resolve `sqlite-android` (API) together with `sqlite-bundled-jvm` (driver). This works because the two are binary-compatible, so check this pairing first if host tests break after an sqlite or Room bump.
- **`@Upsert` is not used** (2026-11-02, REP-24). Room 3's `EntityUpsertAdapter` tells an update-worthy conflict apart from other failures by parsing the exception message, and on the Android host tests the exception arrives without one (the mockable `android.jar` drops it), so the adapter rethrows. Production is unaffected. Writes use `@Update` (returning the row count) and fall back to `@Insert` when it is `0`, inside a transaction. Never use `@Insert(onConflict = REPLACE)`: it deletes and reinserts the row, which cascades to its children. Never branch on `SQLiteException.message`. See ADR-0023.
